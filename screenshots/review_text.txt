"""
LM5165Y buck converter: 24V protected input to 3.3V output.

PFM mode (RT shorted to GND) for 10.5uA quiescent current.
RILIM = 56k for 120mA peak / 50mA max PFM output.
Design follows TI Design 2 (Section 8.2.2, Figure 50).

Topology:
  VIN (24V) --+-- C1 (4.7uF 50V) --+-- GND
              |                      |
              +-- C_VIN (100nF 50V) -+
              |
           U_BUCK.VIN
              |
           U_BUCK.SW --- L1 (68uH) --- VOUT (3.3V)
              |                           |
           U_BUCK.VOUT --+-- C2 (22uF) --+-- GND
                         |
                         +-- C6 (1uF 50V) --- GND

  RT -> GND (PFM mode)
  EN -> VIN (always on, internal UVLO at 2.9V)
  ILIM -> R_ILIM (56k) -> GND
  SS -> open, HYS -> open
  EP -> GND
  PGOOD -> MCU (open-drain, needs external pull-up)

Note: LM5165 VSON-10 has internal bootstrap — no external BST cap needed.
"""

module BuckConverter:
    """
    LM5165Y synchronous buck: 24V -> 3.3V, PFM mode, 10.5uA Iq.
    150mA max output, 120mA peak current limit (RILIM=56k).
    """

    # --- External interfaces ---
    power_in = new ElectricPower
    """24V protected input rail."""

    power_out = new ElectricPower
    """3.3V regulated output rail."""

    pgood = new ElectricLogic
    """
    Power-good output (open-drain). Goes high when 3.3V is in regulation.
    Needs external 10k pull-up to 3.3V (in MCU module).
    """

    # --- IC ---
    u_buck = new Texas_Instruments_LM5165YDRCR_package

    # --- Inductor ---
    l1 = new XR_XRNR4018_68uH_M_package
    """68uH, 470mA Isat, 1 ohm DCR, 4x4mm shielded."""

    # --- Input capacitors (24V rail, need 50V rating) ---
    c1 = new FH_1206B475K500NT_package
    """4.7uF 50V X7R, 1206. Bulk input energy reservoir."""

    c_vin = new YAGEO_CC0603KRX7R9BB104_package
    """100nF 50V, 0603. HF decoupling tight to VIN/GND pins."""

    # --- Output capacitors ---
    c2 = new TDK_C2012X5R1A226KT000N_package
    """22uF 10V X5R, 0805. Output ripple smoothing."""

    c6 = new Samsung_Electro_Mechanics_CL10A105KB8NNNC_package
    """1uF 50V X5R, 0603. Internal VCC LDO decoupling on VOUT."""

    # --- Current limit resistor ---
    r_ilim = new Resistor
    r_ilim.resistance = 56kohm +/- 1%
    r_ilim.package = "0603"

    # === Power connections ===

    # VIN rail
    power_in.hv ~ u_buck.VIN
    power_in.hv ~ c1.p1
    power_in.hv ~ c_vin.p1

    # Input caps to GND
    c1.p2 ~ power_in.lv
    c_vin.p2 ~ power_in.lv

    # GND connections
    power_in.lv ~ u_buck.GND
    power_in.lv ~ u_buck.EP
    power_in.lv ~ power_out.lv

    # === Control pin connections ===

    # EN -> VIN (always on; internal UVLO at 2.9V handles startup)
    u_buck.EN ~ power_in.hv

    # RT -> GND (PFM mode, no timing resistor)
    u_buck.RT ~ power_in.lv

    # ILIM -> 56k -> GND (120mA peak current limit)
    u_buck.ILIM ~> r_ilim ~> power_in.lv

    # SS -> open (internal 900us soft-start) — no connection needed
    # HYS -> open — no connection needed

    # === Output path ===

    # SW -> L1 -> VOUT
    u_buck.SW ~ l1.p1
    l1.p2 ~ u_buck.VOUT

    # VOUT rail
    u_buck.VOUT ~ power_out.hv
    u_buck.VOUT ~ c2.p1
    u_buck.VOUT ~ c6.p1

    # Output caps to GND
    c2.p2 ~ power_out.lv
    c6.p2 ~ power_out.lv

    # === PGOOD output ===
    u_buck.PGOOD ~ pgood.line
    pgood.reference ~ power_out

"""
Heater driver + TPL5010 watchdog + SCR latch safety circuit.

Q1 (XCHS3N12 N-FET) switches 24V heater current. TPL5010 external watchdog

PGOOD-gated arming: Q_ARM (N-FET in R_FB path) prevents the latch from
self-sustaining until RC-delayed PGOOD charges arm_node above Vgs(th).
This prevents the TPL5010 power-on reset (~60ms) from permanently
triggering the latch at every boot. Arming delay ≥361ms (3.6× margin).

Gate-kill circuit:
  MCU timer → R_GATE (1k) → gate_node → R4 (10k) → GND
                                  ↑
                             Q_WD drain
                             Q_WD source → GND

                                            ↑                               ↑          ↑
                                      R_WD_PD (10k) → GND           arm_node    R_LATCH_PD (1M) → GND

                                            ↑  ↑          (anode)   (cathode)    ↑
                                            |  R_PNP_BASE (100k) → 3.3V
                                      Q_LATCH collector          R_WD_PU (100k) → 3.3V

Latch arm circuit:
  PGOOD → R_ARM (1M) → arm_node → C_ARM (1uF) → GND

                      Q_ARM gate
"""

    and Q_LATCH is off (normal operation). Without this, the PNP base floats
    and leakage/noise could cause spurious heater lockout. 100kΩ gives 140×

    easy latch trigger (hFE needed = 1.4 vs MMBT3904 min 100)."""

    q_arm = new Changjiang_Electronics_Tech_2N7002_package
    """N-FET in R_FB path. Breaks latch feedback loop until PGOOD charges
    arm_node above Vgs(th). Prevents TPL5010 power-on reset from triggering
    permanent heater lockout."""

    r_arm = new Resistor
    r_arm.resistance = 1Mohm +/- 1%
    r_arm.package = "0603"

    Arming delay ≥361ms (Vgs(th) min) vs 100ms max TPL5010 tRST."""

    """1µF arm delay cap. Holds arm_node low during power-on reset,
    preventing latch feedback until RC charges past Q_ARM threshold."""

    # --- Internal nodes ---
    gate_node = new Electrical
    """Q1 gate: R_GATE output, R4 top, Q_WD drain."""

    pnp_coll_node = new Electrical
    """Q2_INV collector: R_WD_PD top, Q_WD gate, R_FB input."""

    pnp_base_node = new Electrical
    """Q2_INV base: R_BASE output, Q_LATCH collector."""

    """D_ISO anode: R_BASE input (between D_ISO and PNP base)."""

    fb_out_node = new Electrical
    """R_FB output / Q_ARM drain junction."""

    latch_base_node = new Electrical
    """Q_LATCH base: Q_ARM source, R_LATCH_PD top."""

    arm_node = new Electrical
    """PGOOD-delayed arm signal. RC charges from PGOOD through R_ARM."""

    # 24V → heater_hi, heater_lo → Q1 → GND
    heater_hi ~ power_24v.hv
    heater_lo ~ q1.D
    q1.S ~ power_24v.lv

    # Flyback diode across heater (anode at Q1 drain, cathode at 24V)
    d4.A ~ heater_lo
    d4.K ~ heater_hi

    # Bulk cap on 24V rail
    power_24v.hv ~ c4.p1
    c4.p2 ~ power_24v.lv

    # === Gate drive path ===

    # MCU timer → R_GATE → gate_node → R4 → GND
    gate_drive ~> r_gate ~> gate_node
    gate_node ~> r4 ~> power_24v.lv

    # Q1 gate
    gate_node ~ q1.G

    # Q_WD clamps gate to GND on fault
    q_wd.D ~ gate_node
    q_wd.S ~ power_24v.lv

    # === TPL5010 watchdog ===

    u_wdt.VDD ~ power_3v3.hv
    u_wdt.GND ~ power_3v3.lv

    # Bypass cap
    power_3v3.hv ~ c_wd.p1
    c_wd.p2 ~ power_3v3.lv

    # Timeout resistor (11k → ~9.6s period)
    u_wdt.DELAY_M_RST ~> r_delay ~> power_3v3.lv

    # MCU interface
    u_wdt.WAKE ~ wake
    u_wdt.DONE ~ done

    # DONE pull-down: keeps DONE low when MCU is in reset/unpowered,
    # preventing floating input from confusing TPL5010
    r_done_pd = new Resistor
    r_done_pd.resistance = 100kohm +/- 1%
    r_done_pd.package = "0603"
    done ~> r_done_pd ~> power_3v3.lv

    # RSTn with pull-up
    u_wdt.RSTn ~ rstn
    rstn ~> r_wd_pu ~> power_3v3.hv

    # === SCR latch circuit ===

    # PNP inverter (Q2_INV): emitter → 3.3V, base via R_BASE/D_ISO
    q2_inv.E ~ power_3v3.hv
    q2_inv.B ~ pnp_base_node
    q2_inv.C ~ pnp_coll_node

    # PNP collector drives Q_WD gate + feedback (through PGOOD-gated Q_ARM)
    pnp_coll_node ~ q_wd.G
    pnp_coll_node ~> r_wd_pd ~> power_3v3.lv
    pnp_coll_node ~> r_fb ~> fb_out_node

    # Q_ARM gates the feedback path: latch can't sustain until armed
    q_arm.D ~ fb_out_node
    q_arm.S ~ latch_base_node
    q_arm.G ~ arm_node

    # D_ISO: cathode at RSTn, anode → R_BASE → PNP base
    d_iso.K ~ rstn
    d_iso.A ~ d_iso_anode_node
    d_iso_anode_node ~> r_base ~> pnp_base_node

    # NPN latch (Q_LATCH): collector → PNP base node, emitter → GND
    q_latch.C ~ pnp_base_node
    q_latch.E ~ power_3v3.lv
    q_latch.B ~ latch_base_node

    # PNP base-emitter pull-up (defines OFF state in normal operation)
    pnp_base_node ~> r_pnp_base ~> power_3v3.hv

    # === PGOOD-gated latch arm ===

    # RC delay: PGOOD → R_ARM (1MΩ) → arm_node → C_ARM (1µF) → GND
    # τ = 1s. Arming delay ≥361ms (worst-case Vgs(th)=1.0V) vs 100ms max tRST.
    # At power-on: arm_node low → Q_ARM off → R_FB disconnected → latch disabled.
    # After ~400-800ms: arm_node charged → Q_ARM on → latch armed for real faults.
    pgood ~> r_arm ~> arm_node
    arm_node ~ c_arm.p1
    c_arm.p2 ~ power_3v3.lv

    # Latch base pull-down (noise immunity)
    latch_base_node ~> r_latch_pd ~> power_3v3.lv

## 1. RTC Crystal + Software Temperature Compensation

**Goal:** Autonomous timekeeping with <5 min/year drift when not
connected to a logger.

**Parts to add:**
- Q13FC13500004 (C32346) -- 32.768 kHz crystal, +/-20 ppm, SMD3215-2P,
  basic (no setup fee), $0.18, 659K stock, CL = 12.5 pF
- 2x FH 0402CG180J500NT (C1549) -- 18 pF C0G/NP0 50V, 0402,
  **basic** (no setup fee), $0.001 each, 1.5M stock.
  18 pF gives CL = 12.0 pF assuming 3 pF stray. STM32 RTC CALR
  calibration register compensates +/-488 ppm, so exact cap value is
  non-critical. Tune after first board bring-up if desired.

**Firmware:**
- One-time frequency calibration using STM32 RTC smooth calibration
  register (+/-488 ppm range, 0.954 ppm steps). Eliminates initial
  +/-20 ppm crystal tolerance.
- Software temperature compensation using STM32 internal die temp
  sensor (+/-1.5C). Crystal parabolic model:
  delta_f/f = -0.034 ppm/C^2 * (T - 25)^2
- RS-485 time sync from logger when connected (eliminates long-term drift).

**Expected accuracy:** ~1.3 min/year worst case (0C winter), ~0.3 min/year
at typical forest temps (10-30C). No dedicated crystal temp sensor needed --
MCU sleeps 99.3% of the time so die temp ~= ambient.

**MCU pins:** PC14 (OSC32_IN), PC15 (OSC32_OUT) -- dedicated RTC crystal
pins, no conflict with existing assignments.

**Layout constraints:** Crystal traces < 5 mm. Ground guard ring around

## 2. ADC Architecture: Dual Mux, 32 Thermistor Channels

**Goal:** Support up to 8 sap flux probes (4 thermistors each = 32
channels) with a single ADS1115, using two cascaded 16:1 analog muxes.

**Change:** Remove one ADS1115. Add 2x 74HC4067 16:1 analog muxes.
All thermistor lines route through muxes into ADS1115 AIN0. Excitation
sense goes directly to AIN1 (single-ended ratiometric measurement).

| | v1.0 (2x ADS1115) | v1.1 (1x ADS1115 + 2x mux) |
|---|---|---|
| ADC chips | 2 | 1 |
| Max thermistors | 6 | 32 (2x 16-channel mux) |
| Resolution | 16-bit | 16-bit (same ADC) |
| Interface | I2C | I2C + 4 GPIO (shared select) + 2 GPIO (enables) |
| Idle power | 1 uA | 0.5 uA + ~0 (mux is CMOS, nA leakage) |
| Price delta | -- | -$0.16 (drop ADC + passives, add 2x mux) |

### Mux part

74HC4067PW,118 (C179326) -- Nexperia, 16:1, 80 ohm Ron, TSSOP-24,
31K stock, $0.57 each, extended. Qty 2.

### How it works

Two muxes share select lines S0-S3 (4 GPIOs). Each mux has its own
enable pin (~E, active low). Only one mux is enabled at a time:

```
Thermistors 1-16  → Mux A (channels 0-15) → ──┐
                                                ├→ ADS1115 AIN0
Thermistors 17-32 → Mux B (channels 0-15) → ──┘
```

Firmware cycle: set S0-S3 → enable mux A (disable B) → start ADC →
read result → next channel. After mux A channel 15, switch to mux B.

Enable toggling prevents crosstalk: the disabled mux's output is
high-impedance, so charge injection from its channels can't corrupt
the active measurement.

### Single excitation line

One GPIO pin (PC6) drives all 32 thermistor half-bridges through a
single RC filter:

- R_EXC = 270 ohm (C22966, UNI-ROYAL 0603WAF2700T5E, basic, $0.001)
- C_EXC = 1 uF (C15849, existing BOM)
- Filter cutoff: fc = 1 / (2 * pi * 270 * 1e-6) = 589 Hz

At 8 sensors (32 half-bridges, ~20k each): R_load = 625 ohm.
V_exc = 3.3 * 625 / (625 + 270) = 2.30V. I_steady = 3.7 mA.
I_inrush = 3.3 / 270 = 12.2 mA (safe, under STM32 20 mA GPIO limit).

Firmware: enable PC6 before scan, read all 32 mux channels across
both muxes, disable PC6. Simpler than dual-excitation (no per-group
enable/disable sequencing).

### Excitation sense: ratiometric on AIN1

The single excitation line connects to AIN1 through a 1k series
resistor + 100 nF filter cap (matching the thermistor path protection).
Firmware reads excitation as a **separate single-ended conversion**
(AINp=AIN1, AINn=GND) once per scan cycle, then divides each
thermistor reading by excitation to get ratiometric values:

  T = steinhart_hart(V_therm / V_exc)

Ratiometric measurement cancels excitation voltage uncertainty
(GPIO output variation, R_EXC voltage divider, supply noise). The
2.30V excitation is not a problem — only the ratio matters.

This loses hardware differential CMRR vs v1.0, but:

- Ground bounce is already managed (no ADC during heater pulses)
- Common-mode noise during quiescent reads is minimal (no switching)
- Avoids adding an analog switch IC (saves BOM complexity)
- Temperature differencing (heated - reference) cancels remaining
  systematic errors

AIN2, AIN3: tied to AGND through 1k resistors (prevent noise coupling).

### Scan rates and noise

ADS1115 data rates and noise (PGA = +/-4.096V, LSB = 125 uV):

| Data Rate | Conversion Time | Noise (uVrms) | Temp Noise (mC) | 32-ch Scan | Scan Rate |
|-----------|----------------|---------------|-----------------|------------|-----------|
| 8 SPS | 125 ms | 7.8 | 0.6 | 8.0 s | 0.13 Hz |
| 16 SPS | 62.5 ms | 11 | 0.9 | 4.0 s | 0.25 Hz |
| 32 SPS | 31.3 ms | 16 | 1.3 | 2.0 s | 0.50 Hz |
| 64 SPS | 15.6 ms | 23 | 1.8 | 1.0 s | 1.0 Hz |
| 128 SPS | 7.81 ms | 31 | 2.5 | 0.50 s | 2.0 Hz |
| 250 SPS | 4.0 ms | 47 | 3.8 | 0.26 s | 3.9 Hz |
| 475 SPS | 2.1 ms | 64 | 5.1 | 0.13 s | 7.4 Hz |

**Note:** Each channel requires a dummy conversion after mux switch

## 4. Connector Topology, Multi-Heater Support & Gate Driver

**Goal:** Support 1-8 heater probes with safe, efficient high-current
switching. Anti-footgun design: safe at any pulse duration, any number
of heaters.

### Connector layout: two separate blocks on the same board edge

**Heater block (2-pin):** KF2EDGV-3.5-2P (C441321)
- Pin 1: Heater+ (24V switched)
- Pin 2: Heater- (drain return)
- $0.06, 11K stock, extended
- Width: 7 mm

Users wire 1-8 heater elements in parallel at the cable level. The
board just provides switched 24V. Each heater is ~42 ohm, so 8 in
parallel = 5.25 ohm = 4.57 A total.

**Thermistor/signal block:** 2x24 pin header (48P), XFCN PZ254V-12-48P
(C22465947), $0.30, extended.
- 32 thermistor inputs
- GND (thermistor ground return)
- Excitation (GPIO-switched 3.3V via 270 ohm filter)
- Spare pins for: unused GPIOs, SPI bus, I2C bus, etc.
- See Section 11 for full pinout.

Total connector edge footprint: ~70-80 mm. Fits on the board edge.

**Why separate blocks:**
- Physical isolation of high-current (4.57 A) heater path from
  microvolt-level thermistor signals
- Can disconnect heater cable without disturbing thermistor wiring
- Simpler cable assemblies (power wires are thicker gauge)

### Gate driver circuit (NEW in v1.1)

The v1.0 design drives the heater MOSFET gate directly from a 3.3V
MCU GPIO. At v1.1 currents (up to 4.57A for 8 heaters), even a
low-Vgs(th) MOSFET at 3.3V gate has significant Rds(on) and wastes
heat. A 6-component gate driver boosts gate voltage to 10V from the
existing 24V rail, dropping Rds(on) to spec-sheet values.

**Circuit:**

```
                    R_GATE_PULL (1M)                            Node A
V24_PROT ──────────────────────────────┬───────── Q1 Gate
                                       │
                            D_ZENER (10V, cathode at A, anode to GND)
                                       │
                            Q_DRIVER (drain at A, source to GND)

                                           R_PA8_PU (10k)
                                                │
Q_DRIVER gate path:                            V3V3
    PA8 (MCU) ── R_GATE_DRV (10k) ── Q_DRIVER gate ── R_GATE_PD (100k) ── GND
```

**How it works (normal operation):**
1. PA8 HIGH → Q_DRIVER ON → drain at ~0V → Q1 gate at ~0V
   (R_GATE_PULL sinks 24V/1M = 24µA through Q_DRIVER) → **heater OFF**
2. PA8 LOW → Q_DRIVER OFF → R_GATE_PULL pulls Q1 gate toward 24V →
   D_ZENER clamps at 10V (cathode at gate, anode to GND — zener
   conducts 14µA at steady state) → **heater ON** at full Rds(on) spec

**Inverted logic (PA8 LOW = heater ON).** During normal operation,
firmware drives PA8 HIGH to keep heater off, then briefly drives
PA8 LOW for the 2-second heater pulse.

**Why not N-channel PGOOD gating?** An earlier revision attempted to
place a 2N7002 (Q_PGOOD) in series with R_GATE_PULL to disconnect
the pull-up during boot. This doesn't work: in an N-channel MOSFET
used as a high-side switch, the source voltage follows the output.
As Q1 gate charges above ~2V, Vgs drops below threshold and the
switch turns off — defeating the purpose. A P-channel high-side
switch would work but adds complexity (level shifting for the 24V
gate drive). The R_PA8_PU approach below is simpler and cheaper.

**Boot behavior (R_PA8_PU provides default-ON for Q_DRIVER):**

R_PA8_PU (10k from V3V3 to PA8 node) pulls Q_DRIVER gate HIGH as
the 3.3V rail ramps during buck startup. This makes Q_DRIVER turn
ON before R_GATE_PULL can charge Q1 gate to dangerous levels.

1. Power applied. V24_PROT rises. Buck starts up. R_GATE_PULL (1M)
   begins charging Q1 gate (τ = 1MΩ × 1.8nF = 1.8 ms).
2. V3V3 ramps from 0V to 3.3V (~2 ms soft-start). R_PA8_PU pulls
   PA8 node toward V3V3. Through R_GATE_DRV (10k), Q_DRIVER gate
   voltage = V3V3 × 100k/(10k+10k+100k) = V3V3 × 0.83.
3. When V3V3 reaches ~1.8V (~1.1 ms into ramp): Q_DRIVER gate
   exceeds Vgs(th) ~1.5V → Q_DRIVER turns ON → clamps Q1 gate
   to ~0V. Any charge accumulated on Q1 gate discharges instantly
   (Ciss × Rds(on) = 1.8nF × 5Ω = 9 ns).
4. MCU boots (~2 ms after V3V3 stable). Firmware drives PA8 HIGH
   (same state as pull-up) → seamless handoff.
5. Only after firmware explicitly drives PA8 LOW can heater turn ON.

**Boot glitch: ~1 ms at partial gate voltage.** Between t≈116µs
(Q1 gate reaches Vgs(th) = 1.5V through 1M) and t≈1.1ms (Q_DRIVER
turns ON via 3.3V ramp), the heater conducts briefly. Gate voltage
reaches ~11V before Q_DRIVER clamps it. Worst case energy at 8
heaters: ~106 mJ → 0.11°C wood temperature rise. Thermally
negligible. This is comparable to the v1.0 ~2ms glitch but shorter
due to the 1M pull-up slowing gate charge.

**MCU crash behavior (SCR latch kill path):** If firmware locks up
with PA8 LOW (heater stuck on), the TPL5010 watchdog fires within
9.6 seconds. The kill sequence:

1. TPL5010 asserts RST (active low) on MCU NRST pin
2. D_ISO (1N4148WS) blocks RST from reaching the SCR latch directly
   (latch only triggers through the watchdog path, not MCU resets)
3. Q_LATCH (MMBT3904 NPN + SS8550 PNP cross-coupled) latches ON
4. Q_WD (2N7002, driven by latch output) pulls Q1 gate to GND
   **permanently** — heater OFF until power cycle
5. Latch overrides R_GATE_PULL (1M): Q_WD sinks only 24 µA,
   pulling gate to ~0.1 mV
6. MCU still boots and can report the fault via RS-485 (D_ISO
   isolates latch from NRST so MCU reset works normally)

**Recovery:** Power cycle only. The SCR latch is self-sustaining
once triggered — R_FB (100k) provides base current to maintain the
cross-coupled state. R_LATCH_PD (1M) bleeds the latch when VDD
is removed. This is intentional: a latched heater fault should
require human intervention, not auto-recover.

**Parts:**
- Q_DRIVER: 2N7002 (C8545, already in BOM) -- N-channel, SOT-23
- D_ZENER: MM3Z10 (C19077459, preferred, $0.012) -- 10V, SOD-323
- R_GATE_PULL: 1M (C22935, already in BOM)
- R_GATE_DRV: 10k (C25804, already in BOM)

### D1 (reverse polarity Schottky) upgrade

**CRITICAL FIX:** D1 is in the SERIES power path. Topology from
protection.ato: `J1 → PTC → TVS → D1 → V24_PROT → {buck, heater}`.
D1 carries ALL current including heater (up to 4.57A for 8 probes).
The v1.0 SS36 (3A) is undersized for v1.1.

- **Current:** SS36 (C16015), 3A/60V, SMA
- **New:** SS56 (C18199169), 5A/60V, SMA, **preferred** (no setup fee), $0.045
- Same SMA footprint -- drop-in replacement
- 5A continuous + 120A surge handles 4.57A with margin

**Thermal constraint at 8 heaters:** At 4.57A, Vf ~0.65V →
~3.0W dissipation during the 2-second pulse. SMA transient thermal
impedance at 2s is ~30% of steady-state Rth(j-a): junction rise
~80°C. At 40°C ambient (sun-heated enclosure): Tj ~120°C, leaving
30°C margin to Tj,max=150°C. Acceptable for 2-second pulses every
30 minutes (average power: 0.003W). In extreme heat (>50°C ambient),
margin narrows to ~20°C -- monitor D1 temp on first field boards.

**Layout mitigation:** Place 4-6 thermal vias (0.3mm drill) under
D1's SMA anode pad, connected to the GND plane (In1.Cu). Add a
copper pour on B.Cu under the diode for additional heat spreading.
This reduces Rth(j-a) by ~30-40%, improving the hot-ambient margin.

**Fallback:** If thermal testing at 8 heaters in >50°C ambient
shows Tj approaching limits, upgrade to a higher-rated SMA Schottky
(e.g., SS56 SMA with better thermal specs). Note: SMA and SMC
footprints are NOT compatible (SMA: 4.3x2.6mm, SMC: 7.7x5.9mm).
An SMC upgrade would require a board respin.

### PTC fuse split topology

**Problem:** v1.0 PTC (1.1A hold) is in the series path before both the
buck converter and heater. At 2+ heaters (1.14A), the PTC trips.

**v1.1 topology:**
```
                          ┌→ PTC (1.1A) → buck input (20 mA steady)
J1 → TVS → Schottky → V24_PROT ─┤
                          └→ [6A fuse footprint] → heater MOSFET (4.57A pulsed)
```

- PTC moves from the main series input path (v1.0: before TVS/Schottky)
  to the buck-only branch (v1.1: after the V24_PROT split). It now
  protects only the electronics path (20 mA steady), not the heater.
- Heater path gets a **dedicated fuse** (6A fast-blow, 5x20mm).
  Populated by default — not optional. The fuse is the last line of
  defense for catastrophic shorts (e.g., cable insulation failure in
  the field). User-supplied: any 5-6A fast-blow 5x20mm glass fuse.
- The 4-layer watchdog/latch system handles normal fault modes. The
  fuse handles wiring faults that bypass the electronics entirely.
- Combined input (TVS + Schottky) sees full current (heater + buck)
  during pulses. The TVS only conducts during transients (microamp
  leakage in steady state). The SS56 Schottky handles 4.57A -- see
  thermal note below.

## 5. Input Protection (All Channels)

**Goal:** Identical ESD/EMI protection on all 33 connector-facing analog
lines (32 thermistors + 1 excitation).

Each line gets three protection stages:

1. **TVS array (PRTR5V0U4D):** ESD clamp at connector side. Each IC
   protects 4 lines. 33 lines / 4 = 9 arrays (3 spare channels).
   - v1.0: 2 arrays. v1.1: 9 arrays. Add 7x PRTR5V0U4D (C2835429, $0.06 each).

2. **1k ohm series resistor:** Current limiter + RC filter partner.
   Limits fault current to 3.3 mA. 33 resistors total.
   - v1.0: 7 resistors. v1.1: 33. Add 26x 1k ohm 0603 (C21190, $0.01 each).

3. **100 nF filter cap:** Low-pass filter (fc = 1.6 kHz with 1k ohm).
   Blocks EMI from cables. 33 caps total.
   - v1.0: 7 caps. v1.1: 33. Add 26x 100 nF 0603 (C14663, $0.01 each).

**Zero measurement impact:** The 1k ohm series resistance appears on
BOTH thermistor sense lines AND the excitation sense line (AIN1). In
the ratiometric calculation (V_therm / V_exc), identical voltage
dividers formed by 1k + ADS1115 input impedance (>1 GOhm) cancel.
Mux Ron (~80 ohm) appears only in the thermistor path, but with >1 GOhm
load, the voltage drop is negligible (16 uV from input leakage).

**Unused mux channels:** Tie to GND. Prevents floating CMOS inputs
from coupling noise.

**Cost for additional channels:** +$0.94 (7 TVS + 26 R + 26 C)

## 8. CR2032 VBAT Backup (RTC + Backup Registers)

**Goal:** Keep the RTC running (with calibration intact) across power
cycles and during extended shelf storage, without requiring users to set
the clock at deployment time.

### Why this matters (the Campbell footgun)

Campbell dataloggers use a CR2032 to keep both the RTC *and* RAM alive.
Their VBAT load is 50-100 uA, which drains the coin cell in 3-5 years.
Users routinely discover dead clocks at deployment. Our design draws
**0.8 uA** from VBAT (RTC + LSE oscillator only, no RAM). The CR2032
lasts 24+ years on self-discharge alone.

### STM32G0B1 VBAT domain

| Resource | Survives on VBAT | Notes |
|----------|-----------------|-------|
| RTC (counter + alarms) | Yes | Autonomous 32.768 kHz counter |
| RTC CALR (smooth calibration) | Yes | Hardware pulse add/remove runs autonomously |
| LSE oscillator | Yes | Powers the 32.768 kHz crystal |
| TAMP registers | Yes | Tamper detection + 5 backup registers |
| 5 backup registers (20 bytes) | Yes | General-purpose 32-bit words |
| Temperature compensation firmware | **No** | Needs MCU core + ADC (VDD domain) |
| RAM | **No** | All RAM powered by VDD |

**Key insight:** CALR *does* survive on VBAT. Factory calibration runs
autonomously via hardware pulse correction. Only dynamic temperature
compensation stops when VDD is removed -- OK because shelf storage is
at roughly constant temperature.

### Shelf drift analysis

| Scenario | Temp | Annual drift | 2 years |
|----------|------|-------------|---------|
| Warehouse (20-25C) | 25C | 0.3 s | 0.6 s |
| Cool warehouse | 15C | 3.7 s | 7.3 s |
| Worst case (0C) | 0C | 21.3 s | 42.5 s |

Even worst case: 42 seconds drift over 2 years. Corrected on first
RS-485 contact.

### UX flow

1. **Factory:** Board assembled, CR2032 installed, RTC set to UTC,
   smooth calibration performed. Temperature compensation running.
2. **Shelf:** CR2032 keeps RTC alive with static CALR correction.
   Drift: 0-40 seconds per year at room temp.
3. **Deployment:** User connects 24V. Temperature compensation resumes.
   Clock accurate to <1 minute.
4. **Logger sync:** First RS-485 connection zeros out shelf drift.
5. **LED indication:** Yellow blink = time not sync'd since power-up.
   Green blink = time sync'd.

### Backup register allocation

| Register | Contents | Notes |
|----------|----------|-------|
| BKP0 | Last calibration temp (Q16.16) | For temperature compensation restart |
| BKP1 | Calibration timestamp | When CALR was last tuned |
| BKP2 | Boot counter + flags | Cold boot detection, dirty shutdown |
| BKP3 | Last logger sync timestamp | For drift tracking |
| BKP4 | Reserved | Future use |

### Circuit

```
VDD (3.3V) ─── Anode 1 ──┐
                          ├── Common cathode ──── VBAT pin (STM32)
CR2032+ ────── Anode 2 ──┘
CR2032- ────── GND

Plus 100nF + 1uF decoupling caps on VBAT pin.
```

**Parts:**
- BAT54S (C7420333) -- dual series Schottky, SOT-23, preferred, $0.012
- BS-CR2032-8 (C7498149) -- SMD coin cell holder, $0.21, extended
- 100 nF decoupling cap -- C14663, already in BOM
- 1 uF buffer cap -- C15849 (1uF 50V X5R 0603, basic, $0.01)

The 1 uF cap provides bulk charge during VBAT domain switchover
(VDD drops, BAT54S commutates to CR2032). Without it, a brief
voltage dip on VBAT during the transition could glitch the RTC
counter. The 100 nF handles high-frequency decoupling; the 1 uF
handles the transient current spike.

## 9. RS-485 Auto-Wake UX

**Goal:** Zero-configuration RS-485 responsiveness.

### The problem

RS-485 receiver (SP3485) draws 800 uA always-on. In polling mode
(receiver off, wake every 10s), it drops to ~15-20 uA. But a 10-second
response lag is terrible UX when connecting a laptop in the field.

### Solution: adaptive mode switching

```
                        ┌─────────────────┐
          power on      │  ALWAYS-ON MODE │
        ──────────────► │  (10s safety    │
                        │   boot window)  │
                        └───────┬─────────┘
                                │ 10s expires, no contact
                                ▼
                        ┌─────────────────┐
                        │  POLLING MODE   │◄── idle timer expires
                        │  (10s wake, RX  │    (default 5 min)
                        │   off between)  │
                        └───────┬─────────┘
                                │ RS-485 frame detected
                                │ during polling window
                                ▼
                        ┌─────────────────┐
                        │  ALWAYS-ON MODE │◄── any TX or RX
                        │  (RX enabled,   │    resets idle timer
                        │   instant resp) │
                        └───────┬─────────┘
                                │ idle timer expires
                                │ (configurable, default 5 min)
                                ▼
                        ┌─────────────────┐
                        │  POLLING MODE   │
                        └─────────────────┘
```

### How it works

1. **Boot:** Enters ALWAYS-ON mode for 10 seconds. This lets a connected
   logger immediately establish contact without waiting for a polling
   window. (This is the safety boot window.)
2. **No contact after 10s:** Drops to POLLING mode. MCU wakes every
   10 seconds (EEPROM-configurable), enables receiver for ~5 ms,
   checks for bus activity, goes back to sleep.
3. **First contact:** During a polling wake window, the MCU sees a valid
   MODBUS frame. Switches to ALWAYS-ON mode. Responds immediately.
   Starts idle timer.
4. **Active session:** Every TX or RX resets the idle timer. Response
   latency: <1 ms (USART interrupt from Stop mode).
5. **Session end:** If idle timer expires (default 5 minutes, EEPROM-
   configurable), drop back to POLLING mode.

### Power impact

| Mode | Current from 24V | Notes |
|------|-----------------|-------|
| Polling (default) | ~15-20 uA | Wake every 10s, ~0.05% duty |
| Always-on | ~130-243 uA | SP3485 receiver + USART clocked |

At 8 heaters, heater energy dominates (94% of cycle budget). The
difference between modes is <1 day of battery life out of ~31 days.

### Why no physical button

The first RS-485 frame *is* the button. 10-second worst-case first
contact delay is acceptable. No mechanical failure points.

```
 47     GPIO (PB1)  |  GPIO (PB2)      48
```

**Signal summary:** 32 thermistors, 2 excitation (same net, pin 2+22),
8 GND, 2 I2C, 4 GPIO. Both EXC pins carry the same signal — wired to
the same filtered excitation line. Two pins for convenience (one per
mux group's cable bundle).

**Design rationale:**
- Thermistors grouped in blocks of 4 (one sensor per block). Each
  sensor's wires land on consecutive pins -- breakout board traces
  run straight with zero crossings.
- Mux A sensors (1-4) on pins 1-20, mux B sensors (5-8) on pins
  21-40. Mirrored layout.
- GND fences every 8-10 pins. Double-GND at mux boundary (11/12)
  and mid-group (31/32) for crosstalk isolation.
- Single excitation: one PC6 GPIO drives all 32 half-bridges through
  270 ohm filter (3.7 mA steady). Pin 2 and pin 22 are the same net
  — two physical pins for cable routing convenience.
- Auxiliary block (41-48): I2C for external sensors, 4 spare GPIOs,
  extra GND pair.
- No 3.3V export (PFM-mode buck has ~23 mA headroom during scan but
  ripple is unsuitable for external analog loads; unknown external
  loads could also exceed 50 mA limit during flash writes).

### Physical interface

**Lab/bench testing:** Push Dupont jumper wires or crimp housings
directly onto pin header. No breakout board needed. Wire one sensor
in 30 seconds.

**Field deployment:** IDC ribbon cable from pin header to a breakout
board inside the weatherproof enclosure. Breakout board has screw
terminals grouped per sensor position. Sensor cables enter enclosure
through IP68 cable glands.

**Breakout board** (separate, simple PCB -- just connectors and traces):
- 8 groups of 6-position screw terminals (GND + EXC + 4 thermistors)
- GND and excitation bussed internally per mux group
- Connects to logic board via ~10cm IDC ribbon cable
- Different breakout variants for different deployments (2-sensor,
  4-sensor, 8-sensor)
- Cost: ~$3-5 for PCB + connectors

### PTC inrush: non-issue

Peak inrush: 10-37A depending on cable length, duration 200-700 us.
PTC fuses are thermal devices -- need 100+ ms of sustained overcurrent
to trip. Sub-millisecond capacitor charging pulse cannot trip a PTC.
Steady-state through PTC: ~20 mA (55x below 1.1A hold). Keep as-is.

### Board size: 100 x 80 mm

At 40% component density, estimated minimum area is ~8,630 mm^2.
100x80 = 8,000 mm^2 (tight but feasible with CR2032 on back side).
Stays within JLCPCB's cheapest 100x100mm tier. If layout is tight,
100x90mm gives comfortable margin.

### Extended part fee optimization: not worth pursuing

No basic/preferred alternatives exist for 74HC4067, flash, MOSFET,
or mechanical connectors. The $3 extended fees are one-time per order
(not per board). At 50 boards: $0.42/board. Rounding error vs the
$3.92 flash chip.

## Resolved Items (second batch)

### Excitation simplified to single line

Originally proposed as dual excitation (EXC_A on PC6, EXC_B on PA11)
with both connected to AIN1 through resistors. External review found
that the dual-line AIN1 topology created a summing node — when the
inactive GPIO was low, AIN1 read ~2.0V instead of the expected
excitation voltage.

**Fix:** Single excitation line (PC6 only, 270 ohm R_EXC). Eliminates
the AIN1 summing bug entirely. Frees PA11 as spare GPIO. R_EXC reduced
from 560 to 270 ohm to maintain adequate V_exc (2.30V) at 32 bridges.
Ratiometric measurement (V_therm / V_exc) cancels the voltage divider.

### Pin availability: PD4, PD5, PC8 do not exist on LQFP-48

Verified against atopile package definition. LQFP-48 has only:
PC6, PC7, PC13, PC14, PC15 (no PC0-PC5 or PC8-PC12) and PD0-PD3
(no PD4+). Reassigned: PD4→PA9 (mux A ~E), PD5→PA10 (mux B ~E).
EXC_B eliminated (single excitation on PC6). All with appropriate
boot-state pull resistors.

### Gate driver boot glitch: reduced to ~1 ms

Originally the heater was briefly ON (~2 ms) during every MCU
boot/reset. An earlier revision attempted PGOOD-gating with an
N-channel MOSFET (Q_PGOOD) in the pull-up path, but N-channel
MOSFETs cannot gate high-side pull-ups (source follows output,
Vgs goes negative → switch turns off). Redesigned with R_PA8_PU
(10k pull-up from V3V3 to PA8), which makes Q_DRIVER default-ON
as the 3.3V rail ramps. Combined with R_GATE_PULL increased to
1MΩ (slows gate charge, τ = 1.8 ms), the boot glitch is reduced
to ~1 ms at partial gate voltage. Energy: 106 mJ → 0.11°C wood
temperature rise. Thermally negligible. Sleep current: 24 µA from
24V (R_GATE_PULL through Q_DRIVER), comparable to v1.0 budget.

## Firmware Notes (from external review)

### LSE drive strength (LSEDRV)

The STM32G0B1 RTC_CR register includes LSEDRV[1:0] bits that control
the LSE oscillator drive current. Default is lowest drive (0b00).
At cold temperatures (<-20°C) and with the 32.768 kHz crystal's
increased ESR, the oscillator may fail to start or take >2 seconds.

**Action:** Set LSEDRV = 0b11 (highest drive) during LSE init.
Measure startup time on first boards across temperature range. If
startup is reliable at 0b10 or 0b01, reduce drive to save ~0.1 uA.

### Flash erase scheduling

W25Q256 sector erases (4 KB) take up to 400 ms. Page programs take
up to 3 ms. During erase, SPI is busy and cannot be interrupted.

**Action:** Schedule flash erases during heater-off periods (the
30-minute inter-measurement gap). Never erase during a measurement
scan. Use the W25Q256's suspend/resume feature if an urgent ADC
read is needed mid-erase.

### ADC health monitoring

The ADS1115 ALERT/DRDY pin can signal conversion-ready. If a
conversion doesn't complete within the expected window (2x the
nominal conversion time), the firmware should:

1. Log the timeout to flash
2. Reset the ADS1115 (I2C general-call reset, 0x06)
3. Retry the conversion
4. If 3 consecutive failures: flag the channel as faulted, skip it,
   report via RS-485

### EEPROM write protection

PA12 controls CAT24C32 WP pin (active high = protected). Boot-safe:
10k pull-up holds WP HIGH during reset, blocking all EEPROM writes.
Firmware must drive PA12 LOW before writing config/calibration data,
then drive HIGH immediately after. This prevents accidental EEPROM
corruption during brown-outs or firmware crashes.

### Analog-to-Digital Converters

2x ADS1115 (16-bit I2C, 4-ch each) for 6 thermistor channels. Single-shot mode: 0.5µA idle. Internal reference. Shares I2C bus with EEPROM.

**PGA setting: +/-4.096V (all channels).** The default +/-2.048V FSR saturates on thermistor channels below ~15°C (10kΩ NTC voltage exceeds 2.048V as resistance rises with cold) and cannot read the ~3.2V excitation voltage on AIN3. At +/-4.096V (LSB = 125µV), worst-case temperature resolution is 0.009°C/count at 70°C — still far exceeding the ~0.01°C needed for sap flux measurements. Note: ADS1115 input voltage is capped by VDD (3.3V) regardless of PGA setting.

**East30 sensor specs** (see `east30docs/` for datasheets and QA certs):
- Thermistors: 10kΩ NTC at 25°C, North Star Sensors Curve 44 (Steinhart-Hart 4-coeff, 0-70°C range)
- Reference resistors: 6x 10kΩ, internal to probe (half-bridge dividers built into sensor assembly)
- Heater resistance: ~40-44Ω (measured per-unit on QA cert)
- Cable length: 2m per QA cert, but design supports arbitrary lengths (25m+). All protection, filtering, and signal integrity choices assume long field cables.
- Wiring: 1 excitation (red), 6 thermistor sense wires (color-coded per needle/position), 2 heater (black), 1 ground

**Ratiometric compensation:** The ADS1115 uses a fixed internal reference (2.048V), not the excitation rail. Any drift in the 3.3V excitation (thermal drift, load regulation, PFM ripple) becomes measurement error. Fix: route the filtered excitation voltage (after R_EXC/C_EXC) through R_AIN_EXC (1kΩ series protection + C_AIN_EXC filter, same as thermistor channels) into a spare ADC channel (U_ADC1 AIN3). Firmware reads excitation alongside thermistors and divides out drift, making the system pseudo-ratiometric.

**RS-485 architecture:** No bias resistors. SP3485 has a fail-safe receiver — when the bus is floating (nobody transmitting), the receiver outputs logic HIGH (UART idle/mark). This eliminates the need for bias resistors, which in traditional designs create unpredictable DC current paths through the cable depending on the far-end device's termination and bias network. The receiver stays on during MCU Stop mode (800µA typ / 1500µA max from 3.3V = 130-243µA from 24V battery via buck). STM32 USART wakeup detects a start bit on RX and wakes the MCU from Stop — the logger can reach the adapter instantly by sending any RS-485 data. No polling latency, no wake line, no extra connector pins.

**RS-485 power modes (firmware-configurable, see Firmware Notes):** Default mode is always-on receiver (~130-243µA from battery). For large-scale deployments where per-unit battery cost matters, firmware can switch to polling mode (~15-20µA) by disabling the receiver between configurable listen windows. Hardware supports both modes via split DE/~RE pins — no PCB change needed.

**Heater safety — 4-layer architecture (see Firmware Architecture for details):**
1. **Hardware timer:** STM32 one-pulse mode enforces max pulse duration in silicon.
2. **IWDG watchdog:** Independent RC oscillator resets MCU if firmware hangs → R4 pulls gate low.
3. **External watchdog (TPL5010):** MCU-independent. If MCU fails to pet within ~9.6s, RSTn goes low → PNP inverts → N-FET clamps Q1 gate to GND. Works even if STM32 die is completely dead.
4. **Thermal interlock:** Firmware reads all 6 thermistors before every firing. Refuses if any needle is elevated.

**Gate-kill circuit with SCR latch:**
```
MCU timer ──→ R_GATE (1kΩ) ──→ Q1 gate ──→ R4 (10kΩ) ──→ GND
                                   ↑
                              Q_WD drain
                              Q_WD source → GND
                              Q_WD gate ←── Q2_INV collector ──→ R_FB (100kΩ) ──→ Q_ARM ──→ Q_LATCH base
                                              ↑                                     ↑            ↑
                                        R_WD_PD (10kΩ) → GND                  arm_node    R_LATCH_PD (1MΩ) → GND
                                        Q2_INV emitter → 3.3V                              Q_LATCH emitter → GND
                                        Q2_INV base ←── R_BASE (10kΩ) ←── D_ISO ←── RSTn
                                              ↑  ↑           (anode)    (cathode)      ↑
                                              |  R_PNP_BASE (100kΩ) → 3.3V
                                        Q_LATCH collector                        R_WD_PU (100kΩ) → 3.3V
                                                                                 TPL5010 RSTn (open-drain)
                                                                                 MCU NRST

Latch arm circuit:
  PGOOD → R_ARM (1MΩ) → arm_node → C_ARM (1µF) → GND
                            ↑
                       Q_ARM gate
```
Power-on: PGOOD LOW → arm_node at 0V → Q_ARM OFF → R_FB can't reach Q_LATCH → latch disabled. PNP still activates during TPL5010 POR → Q_WD clamps gate (heater off during reset, good). After ~60ms, TPL5010 releases RSTn → PNP off → heater gate free. Then PGOOD goes HIGH → RC charges → after ≥361ms, Q_ARM turns on → latch armed.
Normal: RSTn HIGH → D_ISO reverse-biased → R_PNP_BASE holds PNP base at 3.3V → PNP OFF → collector ~0V → NPN OFF → MCU controls Q1 freely. Zero power. Q_ARM is on (armed) but no current flows.
Fault: RSTn LOW → D_ISO forward-biased → PNP ON → collector HIGH → R_FB → Q_ARM (on) → Q_LATCH ON → pulls PNP base LOW → **latched permanently**. D_ISO reverse-biased when latched → RSTn stays HIGH → MCU NRST not held low — MCU boots and reports fault via RS-485. Heater locked out until power cycle.
Latch power: 0.64mA from 3.3V (0.1mA from 24V battery). Only during fault — irrelevant.
RSTn also connects to MCU NRST for belt-and-suspenders reset.

**PGOOD-gated arming is critical:** Without the arm gate, the TPL5010 power-on reset (RSTn LOW for ~60ms at every boot, per datasheet section 7.3.1) would trigger the SCR latch, permanently locking out the heater before the MCU even boots. Q_ARM (N-FET in R_FB path) breaks the feedback loop until PGOOD charges arm_node through a 1MΩ/1µF RC (τ=1s). Worst-case arming delay is 361ms (Vgs(th)=1.0V) vs 100ms max tRST — 3.6× safety margin. All three arm components (2N7002, 1MΩ, 1µF) use existing BOM part numbers.

**D_ISO is critical:** Without the isolation diode, Q_LATCH (when latched) pulls the PNP base to 0.2V. R_BASE (10kΩ) forms a voltage divider with R_WD_PU (100kΩ) → RSTn = 0.48V, which is below the STM32 NRST LOW threshold (~1.1V). The MCU would be stuck in permanent reset and unable to report the fault. D_ISO (1N4148WS) blocks this reverse current path. At -40°C with hFE=50, trigger still has 29× margin.

**TPL5010 RSTn + SCR latch:** The TPL5010 RSTn output is a pulse (~60ms typ, 100ms max), not sustained. The cross-coupled PNP/NPN latch (Q2_INV + Q_LATCH) converts this pulse into a permanent hold: one RSTn LOW pulse triggers the latch (when armed), which keeps the PNP saturated and Q_WD gate clamped indefinitely — even after RSTn returns HIGH. The latch can only be cleared by a power cycle (removing battery/solar). D_ISO (1N4148WS, in series with R_BASE) isolates the latch from the RSTn/NRST net: when latched, D_ISO is reverse-biased, so the MCU still resets and boots normally — it can report the fault via RS-485, but cannot fire the heater until manually power-cycled. This is intentional: TPL5010 only fires when layers 1 (timer) and 2 (IWDG) have both failed, indicating a serious fault. Permanent lockout is the appropriate response.

### ADC Input Protection

The 6 thermistor lines and excitation sense line travel through potentially long cable runs (25m+, via J2) to the ADC inputs. Each line is protected by a PRTR5V0U4D TVS array at the connector side (clamps ESD transients before they reach any downstream components), followed by a 1kΩ series resistor and 100nF shunt cap forming an RC low-pass filter (fc = 1.6kHz) that dumps HF noise from long cables to ground before it reaches ADC silicon. TVS placement at the connector side is critical — placing the 1kΩ resistor before the TVS would allow multi-kV ESD voltages to develop across the 0603 resistor before the TVS can clamp.

### Thermistor Excitation Filter

The ADS1115 uses an internal reference (not ratiometric), so any noise on the excitation driving the thermistor dividers directly becomes measurement error. An RC filter cleans up noise before it reaches the thermistors. R_EXC is 560Ω — low enough for acceptable DC drop with ratiometric compensation (2.52V worst-case at 85°C), but high enough to limit GPIO inrush current to 5.8mA when charging C_EXC from 0V (100Ω would draw 33mA, exceeding STM32's 20mA per-pin spec).

**GPIO-driven excitation:** Excitation is sourced from an MCU GPIO (push-pull, ~3.25V at 1mA) rather than the 3.3V rail directly. This allows cutting ~1mA excitation current during sleep by setting the GPIO low before entering STOP2. The ratiometric measurement (AIN3) compensates for any GPIO output voltage variation. On wake: set GPIO high → wait ~3ms for C_EXC to charge (5× RC at 560Ω × 1µF) → read ADCs.

## Design Documentation

### Power

#### Connector

4-pin M8 A-coded connector (J1). PCB side has male pins so the cable is female-to-female — exposed cable ends can't accidentally short.

**Pinout** standardized by IEC 61076-2-104 / IEC 60947-5-2:

| Pin | Color  | Our Assignment | Convention |
|-----|--------|----------------|------------|
| 1   | Brown  | 24V (V+)       | Supply positive |
| 2   | White  | RS-485 A+      | Signal |
| 3   | Blue   | GND (0V)       | Supply return |
| 4   | Black  | RS-485 B-      | Signal |

Watch out: black is **not** ground. In the M8 world, blue is ground.

**Shield capacitor (C5, 100nF 50V):** AC-couples the M8 housing to GND. Shunts high-frequency EMI while blocking DC ground loop current on long cable runs.

#### Protection Circuit (F1, D2, D1)

```
J1 Pin 1 (24V) --> [F1 fuse] --> node A --> [D1: anode->cathode] --> +24V Protected
                                    |
                                  [D2 TVS]  (cathode at node A, anode to GND)
                                    |
                                   GND
```

**F1 (PTC fuse, 1.1A hold, 60V):** Series fuse. Cuts power on overcurrent. Also current-limits TVS during transients.

**D2 (TVS, SMAJ33A, 33V standoff, ~53V clamp):** Parallel voltage clamp. Absorbs transient spikes. 33V standoff gives 4V margin above solar max (29V+).

**D1 (Schottky, SS36, 60V/3A):** Series reverse-polarity protection. ~0.5V forward drop.

### Firmware Architecture

#### Vision
Async `no_std` Rust library (Embassy on STM32G0):

```rust
sensor.read_temperature(Channel::UpperTip).await   // -> Result<Temperature, SapFluxError>
sensor.fire_heater(Duration::from_secs(2)).await    // -> Result<(), SapFluxError::TooHot>
sensor.conduct_measurement(config).await            // -> Result<SapFluxData, SapFluxError>
```

The MCU earns its keep as a safety interlock and protocol handler. Main loop must service TPL5010 WAKE interrupts by asserting DONE (rising edge) within the ~9.6s watchdog period — this is the heartbeat that keeps the external watchdog from killing the heater path and resetting the MCU.

#### State Management

**RAM (volatile):** Measurement state, sample buffers, session counters. Should reset on power loss.

**EEPROM (persistent, rare writes):** Calibration coefficients, device ID, channel mapping, config presets, RS-485 node ID, RX power mode (always-on vs polling).

**Thermistors as physical state (heater safety):** On every heater request, MCU reads all 6 thermistors. If any needle is elevated above ambient (>0.5°C above reference channels), request is refused with `TooHot`. Also flags if any single needle diverges significantly from the others (e.g., one at 50°C while the rest are at 25°C) — indicates a stuck heater, sensor pulled from wood, or hardware fault. Measures physical reality rather than trusting a bookkeeping entry.

#### Firmware Notes

**TPL5010 sync:** Use EXTI interrupt on the WAKE pin. When the TPL5010 pulses WAKE, assert DONE immediately in the ISR. Don't use a free-running timer — the TPL5010's RC oscillator drifts relative to the STM32's clock, so syncing to WAKE keeps the heartbeat aligned.

**I2C bus arbitration:** ADCs and EEPROM share the bus. EEPROM page writes block for ~5ms. Do not start an EEPROM write during a time-critical ADC measurement sequence. Sequence: (1) perform all ADC reads, (2) then write EEPROM if needed. Embassy's async I2C driver handles bus-busy naturally, but the application must order operations correctly.

**Ratiometric ADC reads:** For each measurement cycle, read U_ADC1 AIN3 (excitation voltage) alongside the 6 thermistor channels. Compute resistance as R_therm = R_ref × (V_ain / V_exc) / (1 - V_ain / V_exc). This cancels excitation drift (including GPIO output voltage variation) and improves absolute accuracy. All channels use PGA = +/-4.096V (see ADC section for rationale).

**Sleep entry sequence:** (1) Turn off excitation (excitation GPIO low). (2) Enter Stop mode. SP3485 receiver stays on (~RE=0). USART remains configured for wakeup on RX start bit. GPIOs maintain state during Stop. In polling mode: firmware sets ~RE=1 before Stop, wakes on timer, briefly enables receiver (~RE=0) to listen.

**Wake/measurement sequence:** (1) Turn on excitation GPIO. (2) Wait ~3ms for C_EXC to charge (5× RC at 560Ω). (3) Read all thermistor channels + excitation on AIN3. (4) If comms needed: set DE=1 to transmit, DE=0 to listen. RS-485 receiver is already on — no enable step needed.

**ADC data rate:** Configure ADS1115 for low SPS (8 or 16 SPS) rather than the default 128 SPS. The 1kΩ series protection resistors + 100nF filter caps + long cable capacitance (design supports 25m+) create a high-impedance source. Lower data rates give the ADS1115's internal sampling capacitor more time to settle, improving accuracy.

**ADS1115 mux settling:** The 1kΩ series resistors + cable capacitance create channel-to-channel memory effects on the ADS1115's muxed front end. After switching channels, perform a dummy conversion and discard the result before taking the real measurement. This adds ~125ms per channel at 8 SPS but eliminates inexplicable inter-channel offsets.

**ADS1115 ALERT/DRDY:** Use the ALERT/DRDY pin (configured as conversion-ready) on each ADC to signal completion via MCU EXTI interrupt. This lets the MCU sleep (WFI) during the 125ms conversion instead of polling the I2C bus, saving power and freeing the bus for other devices.

**USART wakeup from Stop:** The STM32G0 USART peripheral can detect a start bit on the RX pin and wake the MCU from Stop mode. In Embassy, this is the natural async pattern: the executor enters Stop when all tasks are awaiting, and a UART interrupt wakes it. The main loop uses `select()` between `uart_rx.read()` (wakes on RS-485 activity) and a measurement timer (wakes on schedule). No polling, no latency for incoming commands.

**No ADC reads during heater pulse:** With 25m cables, 0.6A heater current through the shared ground wire creates ~800mV ground bounce (22AWG = 53mΩ/m × 25m one-way = 1.32Ω, × 0.6A = 794mV). This shifts all thermistor readings by ~6,400 LSBs (at PGA ±4.096V). The sap flux measurement protocol naturally separates ADC reads (before/after pulse) from the heater pulse itself, but firmware must enforce this constraint: never call ADC read functions while the heater GPIO is active. After the heater pulse ends, wait 10ms before reading ADCs — cable inductance (~25µH for 25m) and parasitic capacitance (~2.5nF) ring at ~637kHz with L/R decay τ=38µs; 10ms gives >250τ for complete settling.

**Runtime configurable RX power mode:** Hardware supports two RS-485 listen modes via EEPROM config, with no PCB changes required (split DE/~RE pins enable both):
- **Always-on (default):** Receiver enabled (~RE=0). USART wakeup from Stop on RX start bit. ~130-243µA from 24V battery (800-1500µA from 3.3V via buck). Zero-latency response to logger commands. Works with any data logger out of the box.
- **Polling mode (advanced):** Receiver disabled (~RE=1) between listen windows. MCU sleeps for a configurable interval (1-60s), wakes briefly (~50ms) to listen, then sleeps again. ~15-20µA from 24V battery. Logger must retry or send a preamble longer than the poll interval. Useful for large-scale deployments (1000+ sensors) where per-unit battery cost dominates.

**Safety boot (anti-bricking):** Regardless of EEPROM RX power mode setting, the receiver is forced ON for 10 seconds after every power cycle. This prevents soft-bricking — if a user sets an aggressive poll interval that their logger can't accommodate, power-cycling the sensor opens a 10-second window to send a "reset config" command.

**Unused MCU pins:** STM32G0B1 has 44 GPIOs; this design uses ~19. Configure all unused pins as analog mode (GPIO_MODE_ANALOG) during initialization — this is the reset default and the lowest-leakage state. Avoid push-pull low which can sink current if a pin accidentally couples to a signal. Floating digital inputs waste power through CMOS input buffer shoot-through and can pick up noise that couples into the analog section.

#### Heater Safety Layers

Designed for unattended deployment in dry/dead trees. At 14.4W (24V into ~40Ω needle), napkin math shows:
- 10s → ~171°C needle temp (safe)
- 30s → ~232°C (smoldering risk)
- 60s → ~264°C (pilot ignition risk)

Four independent layers, any one of which can prevent a fire:

1. **Hardware timer (primary):** STM32 timer in one-pulse mode. CPU triggers the pulse; timer peripheral autonomously enforces max duration. Even if CPU hangs mid-pulse, the timer hardware stops the output on schedule.
2. **Independent watchdog (secondary):** IWDG clocked from independent RC oscillator. If firmware stops petting it, MCU resets. On reset, GPIOs go high-Z, R4 pulls Q1 gate low.
3. **External watchdog + SCR latch (tertiary — MCU-independent):** TPL5010 with ~9.6s hardware timeout (R_DELAY=11kΩ). MCU must assert DONE after each WAKE pulse. If MCU fails (firmware hang, die failure, GPIO latched high), TPL5010 asserts RSTn LOW → triggers cross-coupled PNP/NPN latch → Q1 gate permanently clamped to GND until power cycle. D_ISO (1N4148WS) isolates latch from NRST — MCU boots, reports fault via RS-485, but cannot fire heater. 35nA quiescent — essentially free. Latch adds ~$0.04 BOM (1× MMBT3904 + 1× 1N4148WS + 2× resistors).
4. **Thermal interlock (application layer):** Thermistor check before every firing. No persisted state dependency. Measures physical reality — can't be fooled by stale software state.

### PCB Layout Guidelines
- **4-layer stackup:** Signal / GND / 3.3V / Signal. Dedicated inner ground plane (layer 2) directly below top signal layer gives the best return path for ADC traces and contains buck converter EMI. Inner 3.3V plane simplifies power distribution to MCU, ADCs, and peripherals.
- **Board dimensions:** Target ≤100×100mm (JLCPCB cost sweet spot). ~60×50mm is comfortable for 72 components on 4 layers.
- **Fiducials:** 3x global fiducial marks for JLCPCB pick-and-place alignment. 1mm copper circle with 2mm soldermask opening, placed asymmetrically near board corners.
- **Mounting holes:** Include M3 mounting holes; exact count and placement deferred to layout phase based on final board dimensions and enclosure selection.
- M8 and 10-pin header on opposite edges
- Buck components tight (short SW trace, CIN close to VIN)
- Heater MOSFET near J2
- MCU central, EEPROM nearby
- **Analog isolation:** ADC input traces short, away from buck/heater switching noise. R_AIN resistors and C_AIN filter caps close to J2. Excitation filter (R_EXC/C_EXC) near J2.
- **Trace widths:** 24V/heater ≥0.5mm. 3.3V/signal 0.25mm. GND plane for returns.
- **Thermal relief:** Use spoked thermal relief on M8 connector (J1) GND pins. The connector body is a large thermal slug — without relief, hand-soldering requires excessive heat that can damage the connector or PCB.
- **GND return isolation:** Heater GND return (0.6A pulsed) must not route through the analog ground area under the ADCs. Keep heater power loop (Q1 source → GND plane → J2 GND → heater → Q1 drain) physically separated from the sensitive ADC input area. Star-ground or split-plane approach near ADCs. **J2 ground pin trace split:** J2 pin 3 (GND) carries both 0.6A heater return and ADC ground reference. Split the trace at the connector pad into two paths — a fat trace (≥0.5mm) to the heater power loop area, and a separate quiet trace to the analog ground region — before they merge at the ground plane.
- **D4 flyback diode:** Place near J2 (sensor connector), not near Q1. For 25m+ cables, the inductive energy is in the cable — clamping is most effective at the connector where the cable attaches.
- **C_VIN:** Place 100nF ceramic as close to LM5165 VIN/GND pins as possible, shorter loop than C1. Handles HF switching transients.
- Test pads accessible from board edge
- **D_J2A/D_J2B local decoupling:** Place a 100nF cap (C14663) near the VCC pin of each PRTR5V0U4D TVS array, with short traces to the 3.3V and GND planes. During ESD events, the rail-clamp arrays dump surge current into the 3.3V rail — the local cap absorbs this charge and prevents the rail from jumping.
- **Ground pour on L4 under buck:** Add a copper fill (stitched to L2 GND plane) on the bottom signal layer under the LM5165 and inductor area. Provides additional thermal dissipation and EMI shielding for the switching node.
- JLCPCB 4-layer specs: min 0.127mm trace/clearance, 0.3mm via drill, 0.2mm annular ring
